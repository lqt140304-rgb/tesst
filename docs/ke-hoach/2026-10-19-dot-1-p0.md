# Lê Sơn demo — Đợt 1 (P0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the clickable P0 demo of the Lê Sơn veterinary web system — public site with the approved orbit hero, login portal, customer zone and staff zone — on mock data, verified by unit + e2e tests, published as a private Artifact.

**Architecture:** Vite + React SPA with one hash-routed route table and four zone shells (public, auth, customer, staff) plus a print shell. Feature code talks only to a typed async `api` contract; the mock implementation keeps one versioned JSON document in localStorage with all-or-nothing transactions, capability checks and customer-safe projections, so Codex can later swap it for Supabase. The approved orbit hero is mounted as the original vanilla module.

**Tech Stack:** Vite 8.3.2, React 19.3.0, TypeScript 6.0.3, react-router 8.4.0 (hash router), motion 13.5.1, lucide-react 1.59.0, @fontsource/lora 5.3.0 (static), @fontsource/be-vietnam-pro 5.3.0, idb-keyval 6.3.0, Vitest 5.0.5, Playwright 1.56.1, @axe-core/playwright 4.13.0, ESLint 10 + typescript-eslint 8.71, vite-plugin-singlefile 2.3.3; ffmpeg + Python/PIL for media.

**Spec:** `docs/thiet-ke/QUYET-DINH.md` (authoritative; R1–R28) + `docs/thiet-ke/proposal-customer.md` (copy, customer screens), `proposal-staff.md` (data model §8, API §9, seeds §11, staff screens), `proposal-visual.md` (tokens §2, motion §4, icons §5, photos §6), `proposal-tech.md` (stack, routing §5, shells §6, data layer §7–8, hero port §9, media §11, tests §12, build §13). ## Review Focus

1. **Two tabs, two roles:** staff acts in tab A while the customer watches tab B — a shared video / confirmed request / payment must appear in tab B without reload (cross-tab `storage` sync); a stale staff panel must get the conflict toast, not overwrite. → Task 4 (store test `reloads on storage event`, `version conflict throws ConflictError`), Task 20 journey 3.
2. **Customer navigates by URL to things they must not see:** `#/khach-hang/noi-tru/<other stay id>`, `#/khach-hang/hoa-don/<other invoice id>`, or an unlinked account opening invoices → friendly NotFound / locked page, never data. → Task 11 tests `getStay of another customer's stay throws NotFoundError`, `unlinked gets NotLinkedError`; Task 17 e2e `foreign invoice id shows not-found`.
3. **Vietnamese phone input variety:** `0912 345 678`, `0912.345.678`, `+84 912 345 678`, `84912345678` must normalise to one E.164 for login, sign-up duplicate check and booking dedupe; landlines/short numbers rejected with the friendly message. → Task 2 table test.
4. **Storage unavailable / wiped mid-session (private mode, cleared site data):** app still runs in memory with the banner; a session pointing at a reseeded document logs out cleanly instead of crashing. → Task 4 test `falls back to memory when kv throws`; Task 6 test `session for missing subject resolves to null`.
5. **Day rollover:** opening the demo tomorrow reseeds silently when untouched and shows the "Khôi phục" banner when edited; all seeded dates remain relative (no appointment shown "today" from a stale date). → Task 4 test `freshness: clean reseeds, dirty keeps and flags`; Task 5 test `all seed dates relative to clock`.
